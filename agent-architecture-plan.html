1. Recommendation

Yes, more agents are possible. The best design for this project is a hybrid team with one deterministic orchestrator, six specialist modules and the existing three LLM decision personas.

Do not turn every specialist into another LLM. Keep the existing 9-step Bull/Bear/CIO debate. Add deterministic specialist modules that calculate, classify and validate facts from the same shared evidence package. Only consider another model call when a task cannot be handled reliably by code and the free-provider budget allows it.
Keep

Existing committee

Bull and Bear remain independent, debate through four rounds, and the CIO adjudicates. The evidence gate still blocks BUY when required facts are missing.

Add carefully

Specialist intelligence

Fundamental, technical, valuation, portfolio-risk, catalyst and verification modules provide structured inputs. They do not issue trades or overrule the CIO.

3. Target architecture

Centralized orchestration with parallel, bounded specialists; shared evidence; validation before synthesis; and a final outcome verifier.

4. Proposed agent / specialist roster

The word “agent” here means a bounded specialist with a contract and output. Most specialists are deterministic services, not extra LLM personalities.

01EXISTING · KEEP

Bull Analyst

Builds the strongest evidence-supported upside thesis, responds to Bear and revises when facts demand it.

02EXISTING · KEEP

Bear Analyst

Finds downside, weak assumptions, governance concerns, valuation risks and falsifying evidence.

03EXISTING · KEEP

Chief Investment Officer

Adjudicates the complete four-round debate and returns BUY / HOLD / SELL / DATA REQUIRED.

04NEW · DETERMINISTIC

Evidence & Data Quality

Checks source identity, URL, timestamp, verification status, duplicate facts, stale data and required coverage. Can veto a decision on missing evidence.

05NEW · DETERMINISTIC FIRST

Fundamental Analyst

Extracts reported revenue, profit, margins, debt, cash flow and growth from verified filings/provider records. No invented ratios; no unsupported “quality” score.

06NEW · DETERMINISTIC

Technical Analyst

Uses existing TejHQ EOD history and stored indicators: trend, SMA alignment, RSI, MACD, volume and volatility. Explicitly not intraday/live.

07NEW · DETERMINISTIC

Valuation Analyst

Calculates available valuation multiples and scenario ranges only when verified EPS, cash flow, shares and price inputs exist. Otherwise returns DATA REQUIRED.

08NEW · DETERMINISTIC

Portfolio & Risk Analyst

Checks sector allocation, single-stock concentration, small-cap share, portfolio overlap and drawdown context. MTF only from current verified broker evidence; never assume zero.

09NEW · DETERMINISTIC

News & Catalyst Analyst

Classifies NSE announcements and verified news into results, orders, management, corporate actions and material risks with publication time and source links.

10NEW · DETERMINISTIC

Independent Decision Verifier

Checks the CIO JSON schema, decision gate, cited evidence IDs, stale facts, unsupported numbers, portfolio-rule compliance and internal contradictions. Can downgrade to DATA REQUIRED.

11FUTURE · EVALUATOR

Outcome & Learning Evaluator

Compares prior predictions with later prices and NIFTY50 benchmark using existing prediction/evaluation tables. Reports hit rate and excess return; does not rewrite old decisions.

12CONTROL PLANE · NOT AN LLM

Orchestrator

Chooses stages, manages idempotency, parallel limits, retries, timeouts, budget, evidence snapshots and run completion. Never makes the investment decision.

7. Eight-hour implementation plan

A realistic 480-minute MVP sprint. The deliverable is a working, testable specialist pipeline integrated with the existing committee—not a production trading system.

The 8 hours are an engineering estimate, not a background timer or a guarantee that all external data sources will provide every field. Missing provider data must fail closed, not be fabricated.

8. Definition of done / acceptance tests

A feature is not complete because an agent returns text. It is complete when the system can prove what it used, what it skipped and why.

All new code and plan tables exist only in Development.
Current Bull/Bear/CIO 9-step process still works.
Every specialist output references the shared evidence snapshot.
No new price, history, research-source or scheduler tables.
Stale or missing critical data blocks BUY.
No fabricated financial metrics, targets or citations.
MTF remains UNKNOWN without verified broker evidence.
No F&O or non-Indian instruments enter the advisor scope.
Provider 429/timeout resumes without duplicate records.
Per-ticker fan-out respects rate and concurrency limits.
Agent outputs and failures are visible in the run transcript.
Tests and Vercel Development preview are green before any release request.

9. Risks and controls

RiskWhy it mattersControl
Agent proliferationMore calls increase latency, token use and coordination failures.Six specialist modules are deterministic first; only three existing LLM decision personas.
Conflicting analysisAgents may disagree or reuse the same bad input.One immutable evidence package, explicit contracts, verifier and CIO adjudication.
Stale / delayed dataOld EOD prices can look like live prices.Store as-of time, data class and freshness policy; label EOD, not live.
Missing fundamentalsSome free sources may not expose all statements.Missing values remain null; no invented PE, ROE, debt or target price.
Free model rate limitsMany parallel runs can exhaust the shared provider quota.Shared DB pacing, queue, retries, bounded concurrency and deterministic specialists.
Function timeoutsVercel execution is bounded.Persisted stages and resumable work; no single long request for all tickers.
MTF / trade riskIncorrect borrowing data can cause unsafe recommendations.Read-only analysis; require verified broker evidence; never execute trades.
Backtest biasSurvivorship, look-ahead and transaction costs can make results misleading.Later evaluation must use timestamped point-in-time data and benchmark comparisons.

10. Beyond the 8-hour MVP

Phase 2

Outcome measurement

Run 30/90/180-day prediction evaluations, benchmark excess returns against NIFTY50, track decision changes and confidence calibration. Reuse predictions/evaluations tables.

Phase 2

Corporate action intelligence

Track results dates, dividends, splits, buybacks, pledges and exchange announcements with event-specific source validation.

Phase 3

Portfolio-level CIO

Recommend portfolio-level HOLD / trim / add priorities after sector exposure, concentration, liquidity and MTF costs are verified.

Phase 3

Free-provider resilience

Evaluate free model alternatives and their terms, rate limits and availability. Add adapters only after live tests; no paid keys or silent provider substitution.
