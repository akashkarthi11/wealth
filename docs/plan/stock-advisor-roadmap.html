Stock Advisor Roadmap

The queue work is done and the capacity problem is solved. Reading the code to plan what comes next turned up something bigger: in Production the advisor cannot give advice at all, for a reason that has nothing to do with speed.

Where it stands

The evidence gate cannot open in Production

A decision needs verified prices, verified indicators and a verified financial statement. Only a Fincrux snapshot can become a verified statement, and the project's own rule puts that key in Development only. No key, no snapshot, nothing for the NSE period match to verify. Every Production stock ends at DATA REQUIRED — now in no time and at no cost, but still no advice.

docs/stock-advisor-free-providers.md:16 · stock-advisor-verify.js → no_fincrux_data

Scheduled research does not finish on its own

A debate step is only ever started by something a person did: opening a run, resuming it, or the progress poll while the page is open. The nightly auto-research creates the runs, then nothing moves them along. Close the tab and the research stops where it was.

stock-advisor-debate.js — scheduleWorker called from startDebate, resumeDebate, pumpQueue, getProgress

The CIO is asked for figures that are always empty

Its instructions demand portfolio concentration, single-name exposure, small-cap share, cash and MTF before it sizes anything. The value handed to it is hard-coded as nothing. The holdings to work it out are already in the database.

stock-advisor-debate.js:288 — const concentration = null

Funds and ETFs can never pass

The gate asks every holding for a financial statement and technical indicators, which a mutual fund does not have. Their NAV counts only as a price. So a fund is always DATA REQUIRED, whatever is collected for it.

stock-advisor-evidence.js:47

Capacity is no longer the problem

Work is queued and run one step per call, so nothing is cut off mid-flight and no job blocks another. What is left over waits instead of being lost.

The plan, in order

Each step is worth doing on its own. The order matters: the first one tells us whether the rest is built on anything real.

0

Measure before building

SmallDo first

Deploy, press Run now, read the AI data page. It will say whether NSE answers Vercel's Singapore region at all, whether TejHQ does, and how long a stock really takes. I have never seen this app talk to a provider — every timing I have given you is read off the code, not measured.

Unlocks: knowing which of the steps below are real problems. NSE blocking cloud IPs would change the whole plan.

1

Give the queue more windows

SmallConfig only

Vercel allows a hundred scheduled entries per project and each may fire once a day. Using twenty-four of them, one an hour, turns the queue from four catch-up windows into near-continuous draining. It is a change to one file and costs nothing.

From about 4 minutes of guaranteed work a day to about 21 minutes, without opening a page.

2

Put the debate on the queue

MediumBiggest functional win

Each of the nine debate steps becomes a queue item, the same way a provider call is now. The nightly research then finishes by itself overnight and the report is waiting in the morning. Today it waits for you to open the page.

Unlocks: research that actually runs unattended, which is the point of scheduling it.

3

Open the evidence gate in Production

Your callBlocks everything downstream

Without this the advisor stays silent in Production no matter what else we build. Three ways, and they are not equally honest:

Read the actual filing — follow the NSE announcement to the document it links and take the figures from it. True verification, and the queue can afford the fetch. Largest piece of work, and Phase 0 has to show NSE is reachable first.
Accept the announcement itself — treat an official NSE results announcement as the statement, labelled for what it is: the filing was made on this date, the numbers were not read. Small change, honest if the label is shown everywhere the decision is.
Put the Fincrux key in Production — five stocks a day, and it contradicts the rule currently written in the project docs. If you want this, the doc should change with it rather than quietly.
4

Make the advice mean something

Medium

Work out the real portfolio concentration from the holdings, so the CIO can size a position instead of being asked for a number that is always blank. And give each kind of holding its own evidence list, so a fund is judged on NAV, mandate and costs rather than on quarterly results it will never have.

Unlocks: funds and ETFs stop being permanently stuck, and position sizing stops being guesswork.

5

Score the advisor against the market

MediumTables already exist

Record every call with its date and the price at the time, then come back later and compare it with the benchmark. The two tables for this were created months ago and have never been written to. Until something like this runs, neither of us can say whether the advisor is any good.

Unlocks: evidence about the advisor itself, instead of trust.

6

Clear the unused parts

Small

One table was created for collected data and never used; the code writes somewhere else entirely. Either use it or drop it, rather than leaving two tables that look like they do the same job. Keeping each raw provider response in Blob storage would also give a real audit trail for anything the advisor claims.
