Everything stored for the advisor right now: 4 fund NAVs. No market price, no technical indicator, no announcement, no usable financial statement. That is why no decision has ever been produced — the gate rules were never the blocker, the data was.

Rules you inherit

Never invent data. Company names, tickers, figures — if it is not in the database or a provider response, ask. The NSE problem below is tempting to “fix” by typing in company names. Do not.

Never deploy or push without the owner saying so. GitHub goes through the relay only (scripts/relay-push.sh); this machine cannot reach github.com. Updating GitHub main is the owner's job. Production deploys happen on the words “deploy prod”.

Fincrux allows 5 requests per IST day. Do not spend one to satisfy curiosity without asking first.

Production database reads are read-only. SELECT only, and the connection string from .env.production.local is never printed.

Missions, in order

Each one states how you know it worked. Do not start the next before the current one's test passes.

1

Deploy and confirm TejHQ now returns rows

Small

The regex fix is committed and untested against the real API. Deploying it is the single highest-value action available, because market price and technical indicator are two of the three evidence types the gate requires.

Done whenA collection run stores market_price and technical_indicator rows for the 16 equities. Check the AI data page, or count rows by source_type in wealth_stock_advisor_research_sources.
2

Get real company names into the instruments

Owner decides

Ask the owner for the registered name of each holding, or for a source to take them from. Then NSE matching starts working on its own — the matcher is fine. The next run now prints “read N announcements but none named a saved holding”, which is the signal to watch.

Done whenA collection run stores NSE announcements for at least one holding, and the per-feed line in AI data shows a non-zero matched count.
3

Find out what Fincrux actually sends

Medium

The next failure names the keys the response contained. Read that before spending another request. If the free tier simply omits statements, say so plainly and move to the alternative: verify against the NSE filing instead. Do not quietly lower the bar for what counts as verified.

Done whenYou can state, with the response keys as evidence, whether Fincrux can ever supply a statement on this plan.
4

Open the evidence gate for one holding

Medium

With 1–3 done, a stock may have all three verified types and the full debate can run for the first time. If the financial statement is still the gap, this is where the owner chooses between reading the filing, accepting the announcement with an honest label, or changing the required set. The choice is theirs; present it, do not pick.

Done whenaction_gate reads EVIDENCE_READY for at least one holding and a debate produces a decision other than DATA REQUIRED.
5

Make scheduled research finish unattended

Medium

Debate steps advance only from endpoints a person triggers — opening a run, resuming it, or the progress poll. The nightly job creates runs that then sit still. The job queue built today is the fix: make each of the nine steps a queue item, as the provider calls already are.

Done whenA research run started with no browser open reaches a saved report, and the health endpoint stops reporting “no Stock Advisor report for N h”.
6

Give the CIO the numbers it is asked for

Medium

Its instructions demand portfolio concentration, single-name exposure, small-cap share, cash and MTF before sizing. The value passed in is hard-coded null in stock-advisor-debate.js. The holdings to compute it are already there. Also give each asset class its own required evidence, so a mutual fund is judged on NAV, mandate and costs instead of quarterly results it will never have.

Done whenA report quotes a real concentration figure, and a fund reaches a decision rather than DATA REQUIRED.
7

Score the advisor against the benchmark

Medium

Record each call with its date and the price at the time, then compare later. wealth_stock_advisor_predictions and _evaluations were created months ago and have never been written to. Until this runs, nobody can say whether any of the work above was worth doing.

Done whenPredictions are being written on each run, and one evaluation exists comparing a dated call with the benchmark.

Two corrections to the earlier plan

“The Fincrux key is Development-only.” Wrong. It is set in Production and made 5 real requests. That claim came from reading the project doc instead of the database. Check reality before planning around a document.

“Capacity is the problem.” Wrong. The run finished in 7.9 seconds. The job queue is still worth having for resilience, but it was not what was hurting. The providers were.

Both mistakes had the same shape: a plausible story accepted without evidence. The AI data page exists so the next person does not have to do that.

Where things stand: the TejHQ fix and the provider diagnostics are committed and pushed to claude-dev and development. Production is running the build before them, so none of today's provider fixes are live.
