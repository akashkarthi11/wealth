What I changed in Stock Advisor

Three changes: every scheduled job now runs through a queue, one step per function call; financial statements can become verified by matching the reporting period with an official NSE announcement; and the AI debate is skipped when critical evidence is missing.

1 · Every job now runs through a queue

Vercel stops any one call after 60 seconds. Before, the daily cron ran every due job inside that single call, so a slow job ate the time of the ones after it and a big collection could be cut off halfway. Now the cron only writes the work down; each step is run on its own.

  • No step can be cut off by the 60-second limit. Each item is one provider call, and an item is only started when enough time is left for it.
  • One slow job no longer blocks the others. Each waits its turn as a separate item.
  • Nothing is lost. What is not reached stays queued and runs at the next worker call. A step that fails is tried once more, then recorded as failed.
  • Two workers never take the same item — the claim uses FOR UPDATE SKIP LOCKED.

  • Before: a stock with missing evidence still went through all 9 model calls and always ended at "DATA REQUIRED". Financial statements could never be verified, so every stock ended there.
  • After: a statement can be verified, so the full debate can run. When something is still missing, the answer is saved at once without using the free AI model.

3 · The period match in detail (new)

flowchart TD
  A["Take the ticker's newest Fincrux
financial statement"] --> B{"Already verified
by period match?"}
  B -->|"yes"| Z1["Nothing to do"]
  B -->|"no"| C["Read its latest quarter
from the labels and values
e.g. Q2 FY27 = Sep 2026"]
  C --> D{"Found a period?"}
  D -->|"no"| Z2["Stays unverified
reason: no period in the data"]
  D -->|"yes"| E["Look at this company's NSE announcements:
feed Financial results only
published in the last 400 days"]
  E --> F{"Does one of them mention
the same period?
30-09-2026, Sep 2026, Q2 FY27 ..."}
  F -->|"no"| Z3["Stays unverified
reason: no matching announcement"]
  F -->|"yes"| G["Mark the Fincrux statement VERIFIED"]
  G --> H["Store: rule, period, the NSE link and title, date,
and the note: figures were not compared"]
  classDef ok fill:#dff3f0,stroke:#0f766e,color:#0b3d38;
  classDef no fill:#fdf0d8,stroke:#9a5b00,color:#4d2e00;
  class G,H ok;
  class Z2,Z3 no;
  • It only ever raises a statement to verified. It never changes prices, indicators or NSE items.
  • If the period can't be read, or no NSE announcement matches, it stays unverified. It never guesses.
  • It uses only the database (no extra call to any provider), so it is cheap to run in both places.

4 · What the skipped debate saves

  • Model calls per stock: 9 or more before, 0 after (when evidence is missing).
  • Switch back: set STOCK_ADVISOR_ALWAYS_DEBATE=true to run the full debate even when evidence is missing.
